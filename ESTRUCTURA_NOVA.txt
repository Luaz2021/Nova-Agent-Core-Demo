------------------------------------------------------------------------------------------
1. QUE ES Y COMO SE INSTALA
------------------------------------------------------------------------------------------
- Nova = agente de ingenieria para Google Antigravity (Gemini). Sus leyes estan en GEMINI.md; los hooks (nova_core)
  hacen cumplir con CODIGO lo importante, porque el modelo no siempre obedece reglas escritas.
- Instalar: instalar_nova.bat (Windows) / instalar_nova.sh (macOS y Linux) -> adapters/<sistema>/install.*
- Actualizar: el usuario dice "Nova, busca actualizaciones" -> scripts/actualizar_nova.py lee manifest_master.json
  (SHA-256 de cada archivo; solo baja lo que cambio y verifica cada descarga), lanza el Doctor antes (--estructura)
  y despues, y nunca toca memory/, perfil_usuario.json, claves, hooks.json ni config.json.
- Reparar: scripts/nova_doctor.py --reparar (Windows llama ademas a scripts/nova_doctor.ps1).

4. COMPATIBILIDAD (regla: TODO lo nuevo funciona en Windows, macOS y Linux o lo dice claro)
------------------------------------------------------------------------------------------
- 3 sistemas: hooks y frenos, skills, redactor, carriles, director (CLI agy; criterios en PowerShell o bash),
  estudio web, revision visual, API X-Ray, consultas, arnes de seguridad, radiografia (instalar.py elige el binario),
  Penpot (Node.js), destilador de video (instalar.py), Nova Sync (Linux con rclone), Doctor, actualizador, clonador
  (.bat en Windows; .sh y CLONAR.command en macOS/Linux).
- Solo Windows: voz manos libres, aduana de adjuntos, mascota/monito, guardian de claves, horario, session_guard.ps1,
  pruebas/phantom_test.ps1, seguridad/git_clone_sentinel.ps1.
- Trucos de portabilidad usados (repetirlos): CREATE_NO_WINDOW solo si os.name == "nt"; en macOS/Linux procesos de
  fondo con start_new_session=True; tasklist/taskkill -> os.kill / killpg; winsound -> afplay / paplay / aplay;
  DevToolsActivePort en %APPDATA% / ~/Library/Application Support / ~/.config; Python de Nova = nova_env/Scripts/
  python.exe (Windows) o nova_env/bin/python; en textos para Nova usar <PYTHON> y <NOVA_HOME>/... con barras /.
- .ps1 sin acentos (PowerShell 5.1 los lee en ANSI). Los .sh/.command necesitan el bit de ejecucion en git
  (git update-index --chmod=+x).

5. COMO HACER UN PARCHE SIN ROMPER NADA
------------------------------------------------------------------------------------------
1) Clon LIMPIO fuera de Google Drive (Drive mete desktop.ini dentro de .git y lo rompe). Rama nueva (vX.Y).
2) Privacidad: nada de rutas personales, nombres, cofres de claves, proyectos o datos del autor. En los textos para
   Nova: "el usuario" (GEMINI.md le dice que use el nombre de perfil_usuario.json).
3) Lo que el usuario puede cambiar va en PRESERVAR de herramientas_autor/generar_manifest.py (no se pisa).
4) Si una carpeta/archivo se MUEVE o se RETIRA: el actualizador no borra; que lo aparte el Doctor (con copia en
   backups/) como hace revisar_skills_sueltas().
5) Probar: hooks en una casa falsa (USERPROFILE/HOME a otra carpeta) con rutas de Windows y de Mac; el actualizador
   de punta a punta con NOVA_REPO_RAW_URL=file:///<clon> desde la version anterior; NOVA_DOCTOR_SIN_PS=1 en pruebas.
6) python herramientas_autor/generar_manifest.py --version X.Y, actualizar README (novedades + tabla de sistemas),
   AYUDA.md si hay atajos nuevos, y ESTE archivo.
